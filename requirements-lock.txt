# The exact versions every committed number was measured on.
#
# requirements.txt is the loose list, and it mirrors what the four modules
# auto-install at import.  This file is the opposite:
# it is what a SECOND host installs when the point is to reproduce a hash
# rather than to run the model.
#
# The reason it exists is numpy.  Its ufuncs pick SIMD kernels per
# architecture AND per release, and `np.power(10.0, -H / 5.0)` in catalog.py
# sets `estimated_mass_kg`, which is what the whole ranking runs on.  A numpy
# minor upgrade is exactly the kind of thing that moves a float in the last
# bit, and this project argues every release from bit-identity, so the version
# is part of the measurement.  Same reasoning that made v1.17.4 measure the
# pyarrow CSV engine at 4.8x and REJECT it for moving that column by 1e-13.
#
# Recorded 2026-10-25 on the reference host: CPython 3.14.6, Windows, x86-64,
# the host every .verify baseline since 2026-09-04 was taken on.
# `platform_check.py` is what says whether a host running these actually
# reproduces the reference arithmetic; a matching version list is necessary
# and NOT sufficient, because the C library underneath is not pip's to pin.
#
# THIS FILE WAS RE-RECORDED, NOT TALKED INTO A BUMP.  Until 2026-10-25 it named
# the environment of 2026-09-02 (CPython 3.13.9, numpy 2.2.6, pandas 2.3.3,
# pyarrow 24.0.0), the other machine's, while the baselines were being taken on
# this one under the versions below; nothing recorded which environment a
# baseline came from, so the file had stopped describing the measurements.  The
# re-recording was measured first, both ways, in one checkout: the four verify
# cells built under the old environment check MATCH under this one and the
# reverse (4 of 4 hashes, 151 of 151 columns), and every invariant passes under
# both; see versions.md.  A full-catalog comparison was attempted and not
# completed (the host could not hold it beside other work), so rows outside
# those capped cells were not compared.  The rule stands for the next
# upgrade: a line moves only when a measurement says no number moved, or when
# it cannot reach a float.
#
#     python -m pip install -r requirements-lock.txt
#     python platform_check.py

# --- the pipeline itself -----------------------------------------------------
# A LINE HERE MOVES ONLY IF A MEASUREMENT SAYS NO NUMBER MOVED.  numpy, pandas
# and pyarrow can all reach a float.  pandas 3.0 flips
# platform_reference.json's `pandas.str_dtype` from `object` to `str`, the
# Arrow-backed dtype behind the harness bug in verify.py's header; it moves no
# float (measured), and samebytes' comparison handles both.
numpy==2.5.2
pandas==3.0.5
pyarrow==25.0.1
# 2.32.5 -> 2.34.2 on 2026-09-21, for CVE-2026-25645: insecure temp file reuse
# in `extract_zipped_paths()`, fixed in 2.33.0.  Nothing in this repo calls that
# function, so the exposure was nil; it moved anyway because a reproducible
# environment naming a version with a known CVE is a thing every reader and
# every scanner has to re-litigate.  requests is an HTTP client -- it fetches
# the bytes Stages 1-3 write and touches no arithmetic.
requests==2.34.2
tqdm==4.70.0
yfinance==1.7.0

# --- pandas' own runtime deps, pinned because a date parser is not inert ------
# This repo does no timezone-aware work at all -- the only use of `timezone`
# anywhere is `datetime.now(timezone.utc)`, which is stdlib and reads no
# database -- and every probe matches across these releases, which is the
# evidence that they are inert here.  tzdata reads one release OLDER than the
# 2026-09-02 recording's 2026.4 because that is what the reference host runs.
# WARNING: NOTHING CHECKS THESE LINES AGAINST THE HOST.  platform_check.py
# records only numpy and pandas in its `host` block, so the other nine pins can
# drift with every probe still reporting `match`; the 2026-09-02 recording did,
# for seven weeks.
python-dateutil==2.9.0.post0
pytz==2026.3.post1
tzdata==2026.3

# --- the dashboard, which no headless run needs ------------------------------

# --- campaign tooling, which the pipeline itself never imports ---------------
# quietqueue, the campaign runner, imports it for its memory watcher and its
# supervisor's guard against starting a second queue (without it the
# supervisor starts nothing).  quietqueue itself is a tagged git URL, which
# this file cannot hold (it is installed with --only-binary); its pin is
# requirements-campaign.txt, and `./run.sh setup` installs it from there.
# psutil is pinned here rather than left to quietqueue's `>=`: installed after
# this file, quietqueue finds it satisfied and leaves it.  Deliberately NOT in
# requirements.txt: that file
# asserts in its own first line that it mirrors the modules' _REQUIRED_PKGS,
# and verify_docs.py check 7 holds it to that, so adding psutil there would
# make every pipeline install a process inspector it never calls.  It is here
# because a second host standing the campaign up needs the supervisor and wants
# the memory curve, and discovering the import error after the first cell is the
# wrong time.
psutil==7.2.2
